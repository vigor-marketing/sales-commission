## 5. COS 正式生产备份资料

### 5.1 存储边界

当前生产备份使用**传统 CloudBase COS**。PG Storage 中的资源不参与生产备份与启动恢复。

| 存储体系 | 当前用途 | 是否参与生产备份 |
|---|---|---|
| 传统 CloudBase COS | 运行数据库正式备份与恢复 | 是 |
| PG Storage | 已创建的预留资源 / 独立存储体系 | 否 |

### 5.2 对象命名

正式主备份对象：

```text
sales-commission/财务数据.db
```

历史兼容回退对象：

```text
sales-commission/commission.db
```

当前已确认传统 COS 中有 2 个数据库对象：主对象和兼容对象。主对象由系统持续更新；兼容对象仅用于迁移期间或历史数据恢复回退，系统不会继续将新备份写入旧对象。

PG Storage 中的以下路径不作为生产链路：

```text
financial-data/财务数据.db
```

### 5.3 数据库与备份关系

```text
CloudRun 运行时
└── /data/commission.db
    ├── 业务写入 SQLite
    ├── WAL checkpoint 合并已提交数据
    └── 上传到 COS：sales-commission/财务数据.db
```

容器运行盘不视为永久存储。容器重建、重新发布或实例替换后，系统依靠 COS 备份恢复数据库。

## 6. 自动备份与启动恢复

### 6.1 备份触发规则

| 触发时机 | 行为 |
|---|---|
| 收款或提成计算保存成功 | 防抖后约 800ms 上传一次 |
| 合同变更或删除成功 | 防抖后约 800ms 上传一次 |
| 系统设置保存成功 | 防抖后约 800ms 上传一次 |
| 云托管实例启动后 | 启动约 3 秒后执行一次备份 |
| 服务持续运行 | 每 10 分钟执行一次兜底备份 |

连续短时间写入会合并为一次上传，减少重复请求。

### 6.2 启动恢复顺序

1. CloudRun 容器启动。
2. 尝试从 `sales-commission/财务数据.db` 下载主备份。
3. 主对象不存在或文件头校验失败时，回退到 `sales-commission/commission.db`。
4. 对下载内容执行 SQLite 文件头校验。
5. 通过校验后写入临时文件，再原子替换本地 `/data/commission.db`。
6. 初始化数据库结构，并在空库时补充默认种子数据。
7. 绑定 HTTP 服务并开始接收请求。
8. 启动定时备份任务。

这样可以避免容器刚启动时先接收请求，导致访问到尚未恢复的空数据库。

### 6.3 首次上线说明

如果 COS 中尚无任何备份，首次启动日志出现“未找到可恢复的云端备份”属于初始化情形。系统随后初始化本地数据库，并在启动后执行首次备份。首次备份完成后，后续重启应能从主对象恢复。

## 9. 回滚与恢复演练

### 9.1 版本回滚

发生代码异常时，优先在 CloudRun 控制台将流量切回上一个已验证版本。回滚后重新执行健康检查，并查看该版本日志。不要为排查问题直接删除 COS 主备份。

### 9.2 受控恢复演练

涉及备份模块、数据库路径或容器启动顺序的重大修改后，在低业务时段执行：

1. 记录 COS 主对象的最后修改时间和文件大小。
2. 发布不改变业务数据的验证版本。
3. 在当前版本日志中确认已从主对象恢复数据库。
4. 在页面或 API 核对合同、收款计划、提成历史与系统设置。
5. 确认验证版本再次成功上传主对象。

不要直接删除容器数据或 COS 对象来模拟故障；如需破坏性恢复测试，应先单独确认范围、备份和操作窗口。

在云托管服务 `sales-commission` 的当前线上版本日志中搜索：

| 日志关键词 | 含义 |
|---|---|
| `已从云端恢复数据库备份: COS:sales-commission/财务数据.db` | 主备份恢复成功 |

| `bootstrap failed` | 服务启动初始化失败，需要查看上下文堆栈 |

日志判断应以当前接管流量的版本为准，不要把旧版本残留日志误判为当前版本故障。

## 14. 已知边界与维护建议

- 传统 COS 是当前正式生产备份；PG Storage 不参与当前生产链路。
- `/data/commission.db` 是容器运行盘，不应被视为永久存储。
- 单实例 SQLite + COS 备份不适合作为高并发、多副本数据库方案。
- 最小实例为 1 可减少冷启动并保持定时任务运行，但会产生持续实例费用。
- 备份数据库包含合同、收款和提成等业务数据，应保持私有读写。
- 每月检查一次主对象存在性、最后修改时间、文件大小和日志结果。
- 凭据泄露、人员变更或权限扩大时，应立即轮换凭据并重新发布。
